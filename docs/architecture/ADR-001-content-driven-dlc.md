# ADR-001: DLC поддерживается через индекс контента

Статус: принято

## Контекст

Состав SnowRunner продолжает расти, а текущий проект фиксирует содержимое в `unpack-list-optimized.lst`, `src/modules/data/defaults/renderer.ts`, изображениях и UI-обходах. Это создаёт несколько точек ручного обновления для каждого DLC.

## Решение

Ввести `ContentManifest` как единый read model установки игры. Manifest строится после безопасного извлечения и содержит:

- fingerprint игрового архива;
- источники `base`, `dlc`, `mod`, `backup`;
- относительный путь, source id, entity kind и entity id;
- связи между referenced XML;
- diagnostics и неизвестные поля;
- версию схемы manifest.

Parser не ветвится по `dlc_17`, `dlc_18` и будущим номерам. Ветка допускается только для реального изменения схемы XML и оформляется отдельным adapter/ADR.

## Почему это решение

- новый DLC подключается данными установленной игры;
- один resolver используется списком, редактором, reset и save;
- можно сравнивать установки разных патчей;
- неизвестный контент можно открыть в raw/advanced режиме;
- статический каталог defaults перестаёт быть единственным источником истины.

## Последствия

Потребуются: генератор manifest, стабильная политика precedence, fixture XML, версия экспортного формата и миграция от текущих списков. Первое время старые `DLCs`, `Defaults` и `GameXML.getFile()` будут работать как compatibility layer.

## Отвергнутые альтернативы

- добавлять каждое DLC отдельным if/switch;
- полагаться только на имя сезона из Steam/патчноутов;
- полностью переписывать текущий UI до появления индекса;
- извлекать всю игру всегда без измерения времени/диска.
